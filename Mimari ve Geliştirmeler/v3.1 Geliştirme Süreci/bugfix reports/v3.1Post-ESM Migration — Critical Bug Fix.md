## Bug 1 — Login After Logout (Listener Resurrection)

> [!IMPORTANT]
> **Root Cause:** `isSyncStarted` is a module-scoped `let` inside `firebase-handler.js`. After `handleLogout()` fires, it remains `true`, so the `onAuthStateChanged` callback (triggered by re-login) skips the `startRealtimeSync()` call entirely — leaving all `onSnapshot` listeners dead.

**Fix Location:** [`firebase-handler.js`](file:///c:/Users/muhammed.cer/Desktop/project_Inventory/firebase-handler.js#L471-L502)

```diff
+ window.addEventListener('onAppLogout', () => {
+     isSyncStarted = false;  // Resets gate — next auth state triggers fresh startRealtimeSync()
+ });
```

**How it works:** `auth-engine.js` already dispatches `window.dispatchEvent(new CustomEvent('onAppLogout'))` at logout. This listener resets the flag so `onAuthStateChanged` can re-enter the `startRealtimeSync()` branch on next login — **no page refresh needed**.

## Bug 3 — Non-Admins Cannot Save Approvals

> [!CAUTION]
> **Root Cause:** `window.saveData(window.data)` attempts a **full DB snapshot batch write** across all 13 collections. Firestore rules only grant non-admins write access to specific sub-collections. The whole batch is rejected.

**Fix Location:** [`edm-workflow.js`](file:///c:/Users/muhammed.cer/Desktop/project_Inventory/edm-workflow.js) — Two targeted replacements:

| Function | Old Call | New Call |
|---|---|---|
| `approveStep` (L987) | `window.saveData(window.data)` | `window.saveData('purchaseOrders', window.data.purchaseOrders)` |
| `rejectStep` (L1076) | `window.saveData(window.data)` | `window.saveData('purchaseOrders', window.data.purchaseOrders)` |

Both functions only mutate `purchaseOrders` — there is zero reason to write all other collections.

## Bug 6 — `serviceTableBody` Not Rendering

> [!NOTE]
> **Root Cause:** `renderServicesModule` is only triggered by explicit tab-click (`showAdminTab('purchaseTab')`). If Firebase data arrives **after** the tab is already open, or on initial page load, no re-render fires. The KPI counter works because `renderPurchaseStats` is wired separately — but the table DOM never updates.

**Fix Location:** [`purchase-servises.js`](file:///c:/Users/muhammed.cer/Desktop/project_Inventory/purchase-servises.js#L1593-L1614) (appended at end of file)

```javascript
window.addEventListener('onInventoryDataUpdated', function (e) {
    const { collection } = e.detail || {};
    if (collection === 'serviceRecords' || collection === 'purchaseOrders') {
        window.renderServicesModule();
        window.renderPurchaseStats();
    }
});
```

**How it works:** `firebase-handler.js` dispatches `onInventoryDataUpdated` for every `onSnapshot` callback. This listener auto-rerenders the service table whenever live data arrives — no manual tab navigation required.
